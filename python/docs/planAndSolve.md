# 一、ReAct 的特点、局限性

## （1）ReAct 的主要特点
1、Plan 规划阶段：拿到用户问题，先生成完整结构化步骤列表；
2、Solve 执行阶段：按照计划逐条执行每一步；

## （2）优点
**1、拥有全局视角，长任务不容易跑偏、遗忘目标**
    ReAct 长链路容易走着走着偏离原始目标；Plan‑and‑Solve 一开始就把全部步骤列出来，整体逻辑完整，不容易漏掉子任务。
**2、可解释、可人工干预、可调试**
    计划是人类可读的步骤列表，人可以提前审核、修改、删减计划；执行日志清晰，方便排查问题，适合生产环境审计CSDN博...。
**3、长任务 token 更可控**
    执行每一步不需要把全部历史上下文反复传给大模型，每一步只需要当前步骤依赖结果，减少上下文膨胀，降低 token 消耗。
**4、支持步骤并行执行**
    计划拆解完成后，无依赖的步骤可以并行跑，提升执行效率，ReAct 很难做到并行。
**5、适何复杂多步推理**
    数学计算、数据分析、调研报告，不容易出现跳步骤、漏步骤的问题，这也是论文最初提出的目的，解决 Zero‑shot‑CoT 跳步、计算错误问题ar5iv。

## （3）缺点
**1、初始计划一旦错了，后续全部执行都会出错**
    最致命缺陷：规划阶段如果理解错误、步骤拆分错误，后面执行全部跟着错；静态版本没有纠错能力，一条路走到黑稀土掘金。
**2、灵活性弱，不适合动态变化场景**
    现实环境、工具返回结果经常超出预期，静态计划不会自动适配变化；必须额外实现 ** 重规划 (Replan)** 逻辑，工程复杂度上升。
**3、增加一次规划 LLM 调用开销**
    首先要调用一次 LLM 生成计划，再执行；比简单 ReAct 多一轮大模型调用。
**4、不适合高度不确定的探索式任务**
    任务走向完全未知，无法提前写出完整步骤，强行规划会产出大量无效步骤。
